# STM32 智能蓝牙温度计 — 详细描述

## 项目背景

在日常生活和工业场景中，温度监测是最常见的需求之一。传统温度计只能本地读数，无法远程查看。本项目基于 STM32F103 微控制器，结合高精度温度传感器和蓝牙无线传输，实现了一个既能本地显示、又能手机远程读取的智能温度计。

## 设计思路

### 核心方案选择

- **主控 STM32F103C8T6**：经典 Cortex-M3 内核，72MHz 主频，资源丰富，社区资料充足，适合入门和快速原型开发
- **温度传感器 T117**：相比常见的 DS18B20，T117 支持 I2C 接口，精度更高（±0.1°C），内置平均滤波，无需复杂时序控制
- **蓝牙模块 KT6368A**：SPP/BLE 双模，串口透传协议简单，MCU 只需通过 UART 发送数据即可实现蓝牙传输，无需额外协议栈
- **OLED 显示屏**：0.96 寸 SSD1306，I2C 接口，功耗低，支持中文显示，适合小型设备

### 通信架构

整个系统的通信链路清晰：

```
T117 --I2C--> STM32F103 --I2C--> OLED（本地显示）
                   |
                   +--UART--> KT6368A --BLE--> 手机 APP
```

- T117 与 OLED 使用独立的 I2C 总线（软件模拟），互不干扰
- MCU 通过 UART 将温度字符串发送至蓝牙模块，波特率 115200
- 手机 APP 通过 BLE 扫描连接，接收透传数据

## 固件设计

### T117 驱动

T117 是一颗高精度数字温度传感器，I2C 地址固定（写 0x80，读 0x81），内部寄存器包括：

- 温度数据寄存器（0x00-0x01）：16 位有符号数据，转换公式为 `温度 = 25.0 + 原始值 / 256.0`
- 状态寄存器（0x03）：可通过位 5 判断温度转换是否完成
- 转换指令寄存器（0x04）：控制连续/单次/停止转换模式
- 配置寄存器（0x05）：配置采样频率和平均次数

驱动采用软件模拟 I2C，通过 GPIO 翻转实现时序控制，方便引脚分配和移植。初始化时配置为连续转换模式，每秒 2 次采样，32 次平均滤波。

### OLED 驱动

OLED 驱动同样使用软件模拟 I2C，维护一块 128×64 的显存缓冲区，支持：

- 中英文字符显示（8×16、6×8 字体）
- 浮点数格式化输出
- 区域清屏（防止温度更新时残影）

### 主程序流程

```
初始化 HAL 库 → 配置系统时钟 72MHz → 初始化延时、串口
→ 初始化 OLED → 初始化 T117
→ 显示"智能温度计"标题
→ 主循环：读取状态寄存器 → 检查转换完成 → 读取温度 → OLED 显示 → 延时 500ms
```

## APP 设计

### Android APP

- 语言：Kotlin
- 最低 SDK：32（Android 12L）
- 核心功能：
  - BLE 扫描与连接管理
  - 接收蓝牙温度数据并解析显示
  - 通知栏常驻温度显示（前台 Service）
  - 蓝牙断连自动重连

### HarmonyOS APP

- 语言：ArkTS
- 核心功能：
  - BLE 扫描与连接
  - 接收温度数据并显示

## 硬件接线

所有模块均工作在 3.3V 电源域，共地连接。

| STM32 引脚 | 连接目标 | 功能 |
|------------|----------|------|
| PB10 | T117 SCL | I2C 时钟（软件模拟） |
| PB11 | T117 SDA | I2C 数据（软件模拟） |
| PB6 | OLED SCL | I2C 时钟（软件模拟） |
| PB7 | OLED SDA | I2C 数据（软件模拟） |
| PA9 | KT6368A TXD | USART1 发送 |
| PA10 | KT6368A RXD | USART1 接收 |

## 使用说明

### 烧录固件

1. 使用 Keil MDK-ARM 打开 `STM32/MDK-ARM/Project.uvoptx` 工程
2. 编译工程，生成 HEX 文件
3. 通过 ST-Link 或 USB 转 TTL 模块烧录至 STM32

### 使用 APP

1. 手机安装对应的 APP（Android 或 HarmonyOS）
2. 开启蓝牙，扫描名为 KT6368A 的设备
3. 连接成功后，APP 界面显示实时温度
4. Android 版支持通知栏常驻显示
